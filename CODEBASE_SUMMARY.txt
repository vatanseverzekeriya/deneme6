2. CURRENT ARCHITECTURE
================================================================================

TYPE: Client-Side Only (Single-Player)

Architecture Diagram:
┌─────────────────────────────────────┐
│   Browser Client (Client-Side)      │
│  metin2-style.html                  │
│         ↓                           │
│  rpg-game.js (Game Class)           │
│         ↓                           │
│  Canvas 2D Rendering                │
│  All in-memory state (NO DB)        │
└─────────────────────────────────────┘
           ↓
┌─────────────────────────────────────┐
│   Express Server (server.js)        │
│  - Serve static files               │
│  - WebSocket for live reload ONLY   │
│  - Dashboard UI                     │
│  - NO game logic on server          │
└─────────────────────────────────────┘

KEY CHARACTERISTICS:
- HTML5 Canvas 2D rendering
- Vanilla JavaScript (no frameworks)
- RequestAnimationFrame-based game loop (60 FPS)
- All game state in-memory only
- Resets on page reload
- No persistence layer

3. EXISTING DATA MODELS
================================================================================

CHARACTER CLASSES (4 Total):
  - Warrior (🛡️): Tank - High HP/Defense, Medium Damage
  - Ninja (🗡️): Rogue - Low HP, High Damage, High Speed
  - Shaman (🔮): Healer - Medium HP, High MP, Healing Skills
  - Sura (⚡): Dark Knight - Balanced, Lifesteal Skills

PLAYER MODEL:
  {
    class, name, icon,
    level, xp, xpToLevel,
    hp, maxHP, mp, maxMP,
    damage, defense, speed,
    skills: [3 class-specific skills],
    gold, x, y, size, attackCooldown
  }

SKILL MODEL:
  {
    name, icon, key ('Q'|'W'|'E'),
    damage?, heal?, dodge?, lifesteal?,
    mpCost, cooldown, cooldownRemaining
  }

MOB MODEL (5 Types):
  {
    name, icon, hp, maxHP, damage,
    xp (reward), gold (reward), speed,
    x, y, size, targetCooldown
  }

ITEM MODEL:
  {
    name, icon, type ('potion'|'gold'|'weapon'|'armor'),
    heal?, mana?, value?, damage?, defense?
  }

INVENTORY:
  Array(5) of Item - Simple slot-based system

5. UI FRAMEWORK & COMPONENTS
================================================================================

FRONTEND STACK:
- Rendering: HTML5 Canvas API (2D context)
- HTML: Vanilla HTML5 (no framework)
- CSS: Inline CSS in HTML files
- JavaScript: Vanilla JS (no React, Vue, Angular)
- Graphics: Emoji-based character/item/mob representations

UI COMPONENTS:

1. CHARACTER SELECTION SCREEN
   - Grid layout (2x2 on desktop, 1x1 on mobile)
   - 4 clickable character cards
   - Each card shows icon, name, description
   - Clicking card initializes game with that class

2. HUD (Heads-Up Display)
   - Player name and level
   - HP bar (red, full-width at top)
   - MP bar (blue)
   - XP bar (green, shows progress to next level)
   - Real-time value overlays (HP: 120/150, MP: 80/100, etc.)

3. SKILLS PANEL (Fixed right side)
   - 3 circular skill buttons (one per skill)
   - Shows icon and keyboard shortcut
   - Clickable to activate (or press Q/W/E)
   - Cooldown overlay appears after use
   - Disabled when on cooldown

4. JOYSTICK CONTROL (Fixed bottom-left)
   - Circular base (120x120px)
   - Draggable stick in center
   - Touch/mouse responsive
   - Smooth analog movement

5. INVENTORY (Fixed bottom-center)
   - 5 inventory slots (grid layout)
   - Shows item icon when filled
   - Can use items (1-5 number keys)
   - Empty slots are gray, filled slots are gold-bordered

6. NOTIFICATIONS
   - Damage numbers: Float up from mobs when damaged
   - Loot notifications: Show item name when picked up
   - Level up alerts: Announce new level

7. CANVAS GAME AREA
   - Full-screen or responsive sizing
   - Grid background pattern
   - Characters/Mobs/Drops rendered as emoji

RESPONSIVE DESIGN:
- Mobile joystick support for touch
- Touch-dragging for character movement
- Responsive canvas resizing
- Mobile-optimized button sizes
- Works on phones, tablets, desktops

6. EXISTING MULTIPLAYER/NETWORKING FEATURES
================================================================================

CURRENT STATUS: NONE - COMPLETELY SINGLE-PLAYER

WHAT EXISTS (For Development Infrastructure):
1. WebSocket Server (server.js, lines 33-48)
   - Used ONLY for live reload on file changes
   - Sends 'reload' signal to connected clients
   - NOT used for game logic

2. Connection Tracking (server.js, line 33)
   - Maintains Set of WebSocket clients
   - Counts connected browsers
   - Used only for dashboard display

3. Dashboard (server.js, lines 73-479)
   - Game selector (Basic vs RPG)
   - QR code for mobile access
   - Connection counter
   - Live reload indicator

WHAT DOES NOT EXIST:
- No player-to-player communication
- No server-side game logic
- No multiplayer synchronization
- No player accounts or authentication
- No guild system
- No PvP combat
- No shared world/map
- No chat system
- No party/group system
- No persistence of player data
- No anti-cheat systems
- No player-to-player trading
- No shared loot dropping

WebSocket Current Usage (client-side, metin2-style.html):
```javascript
const ws = new WebSocket('ws://' + window.location.host);
ws.onmessage = (event) => {
    if (event.data === 'reload') {
        window.location.reload();  // Live reload trigger only
    }
};
```

NO GAME DATA IS SENT OVER WebSocket
NO MULTIPLAYER LOGIC IMPLEMENTED
